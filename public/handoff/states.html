Component states

Every component with its states side by side. Classes are BEM (card-scientist, list-research, …) and styled only through tokens.css. Forced classes (.is-hover, .is-focus, .is-active) make states visible without interaction; the real pseudo-classes work too. The site header above and the footer below are the live, default instances.

Buttons and links

Real selectors (:hover, :focus-visible, :active, :disabled) and the forced classes sit in the same rule, so tab to any element to see the live state.

Chips and tags

Chips are buttons (filters) or links (type chips on Stories, aria-current=page); tags are labels. The squircle is native corner-shape with a 15px radius fallback (see squircle.css).

Cards

Each card is an article with one stretched link (the title) so the whole card is clickable but only one tab stop and one link name. Inner links (tags, buttons) sit above it with z-index: var(--z-raised).

Navigation

Header, EN/UK switcher, menu panel. The language switcher links to the same page in the other language (hreflang), current language is aria-current=true.

Footer

Dark theme comes from .theme-dark remapping tokens; no extra dark rules in components.

Breadcrumbs

nav[aria-label] > ol; last item is the current page, not a link. The labels differ here only because this page repeats the landmark.

Search, tag filters, results, pagination

Floating label is pure CSS (:placeholder-shown); every field needs placeholder=" ". Result counts are announced through role=status.

Forms: Connect and Want to help

Server-rendered POST forms that work without JavaScript. Errors keep the typed text (the server re-renders the values) and are tied to the field with aria-describedby; errors are yellow with a ! glyph, never colour alone. Captcha is a placeholder (OPEN QUESTION: which provider, see report).
